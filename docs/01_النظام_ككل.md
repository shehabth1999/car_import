# 1. النظام ككل — مين بيشتغل فين

## 1.1 الطبقات، من تحت لفوق

```
┌─────────────────────────────────────────────────────────────┐
│  المتصفح (React)  —  الشاشات اللي بتشوفها                    │
└───────────────▲─────────────────────────────────────────────┘
                │ HTTP / WebSocket
┌───────────────┴─────────────────────────────────────────────┐
│  Django  —  السيرفر                                          │
│                                                             │
│   modules/         كود Genie الأساسي                        │
│     base           الموديلات الأم، الشاشات، الصلاحيات        │
│     contacts       جهات الاتصال (Partner)                   │
│     crm            العملاء المحتملين (Lead)                  │
│     chat           المحادثات والرسايل                        │
│     whatsapp       الربط بواتساب                             │
│     aistudio       محرك المساعدين الأذكياء                   │
│                                                             │
│   extensions/                                               │
│     car_import ◄── كودنا إحنا كله هنا                        │
└───────────────┬─────────────────────────────────────────────┘
                │
┌───────────────┴─────────────────────────────────────────────┐
│  PostgreSQL (الداتا)   +   Redis (الكاش)   +   Celery (المهام)│
└─────────────────────────────────────────────────────────────┘
```

**Celery** ده عامل بيشتغل في الخلفية. أي حاجة بتاخد وقت — زي إرسال رسالة واتساب
أو تشغيل المساعد الذكي — مبتتنفذش قدام المستخدم، بتتحط في طابور وCelery بينفذها.
عشان كده لما تغيّر كود، لازم تعمل restart للعامل ده كمان، مش للسيرفر بس.

## 1.2 إحنا ضفنا إيه بالظبط

الإضافة بتعمل أربع حاجات، ومفيش خامسة:

**أولاً — جداول جديدة (4):**

| الجدول | بيمثّل إيه |
|---|---|
| `CarDeal` | الصفقة: عميل + عربية + مرحلة + فلوس معلّمة + بيانات الشحن |
| `Vehicle` | العربية نفسها: الماركة، الموديل، الشاسيه، السعر، المورّد |
| `ImportStage` | المرحلة من الـ14: اسمها، ترتيبها، ونص رسالة العميل |
| `StageChangeLog` | سجل: مين حرّك الصفقة من مرحلة لمرحلة وإمتى وإيه اللي اتبعت |

**ثانياً — خانات زيادة على جداول موجودة أصلاً:**

- على **جهة الاتصال** (`base.Partner`): الرقم القومي، الباسبور، الجنسية، بلد
  الإقامة، حالة المبادرة، اكتمال المستندات، الموافقة على التصوير… (10 خانات)
- على **العميل المحتمل** (`crm.Lead`): البرنامج المطلوب، الموديل، السنة، اللون،
  الميزانية، نتيجة فحص الأهلية… (11 خانة)

ده بيحصل من غير migration على الموديولات التانية — Genie عنده ميكانيزم اسمه
`ModelExtension` بيضيف الأعمدة دي وقت التنصيب. **أهميته:** لو شلنا الموديول،
الأعمدة بتفضل فاضية ومش بتكسر حاجة.

**ثالثاً — شاشات وقوايم:**
تطبيق "Car Import" فيه: الصفقات (كانبان/ليست/فورم)، العربيات، سجل الرسايل،
والإعدادات (المراحل). زائد تبويب "Car import" وزرار "Create car deal" على شاشة
الـ Lead بتاعة الـ CRM.

**رابعاً — مساعد ذكي:**
وركفلو في AI Studio اسمه "KA Sales — Aya" ومعاه ست أدوات.

## 1.3 ليه صفقة جديدة مش أوردر بيع؟

ده أهم قرار في المشروع (قرار D24). الأسباب، بالترتيب:

1. **`sales` بيجرّ وراه محاسبة.** تنصيب `sales` بيفرض `account` و`payment` و
   `products`، ومعاهم شجرة حسابات وفواتير وضرايب. الشركة مش عايزة حاجة من دول.
2. **الأوردر بيتكلم بمنطق مبيعات، مش استيراد.** أوردر فيه سطور منتجات وكميات
   وأسعار. إحنا محتاجين: عربية واحدة، 14 مرحلة شحن، ورقم بوليصة.
3. **الفلوس هنا مش محاسبة.** الشركة عايزة *علامة* — "المقدم اتدفع" — يكتبها
   موظف، مش قيد مزدوج.

عشان الاختيار ده يفضل محروس، في أمر اسمه `check_ka_install` بيرفض ويقول لك لو
حد نصّب `sales` أو `account` أو `payment` أو `products` على النسخة دي.

## 1.4 رحلة رسالة واحدة من العميل (الصورة الكاملة)

```
عميل بيبعت واتساب
        │
        ▼
  Meta webhook ──► modules/whatsapp  ──► بيسجّل الرسالة في Conversation
        │
        ▼
  اتفلترت؟  (الموديول مركّب؟ المحادثة عليها AI؟ الرصيد كفاية؟)
        │ آه
        ▼
  aistudio_whatsapp/tasks.py  ──► بيجمّع الرسايل ويبعتها للوركفلو
        │
        ▼
  ┌────────────── الوركفلو ──────────────┐
  │  prepare_turn   ← Python: بيجيب       │
  │                   الصفقة ويكتب        │
  │                   التحذيرات           │
  │        │                              │
  │   gate_needs_ai ← في كلام أصلاً؟       │
  │        │ آه                            │
  │   sales_agent   ← الموديل + 6 أدوات    │
  └────────┬─────────────────────────────┘
           ▼
     الرد بيترجع ويتبعت للعميل
```

**النقطة المهمة:** كل حاجة ممكن تتحسب بـ Python بتتحسب **قبل** الموديل. الموديل
شغلته الوحيدة إنه يفهم كلام العميل ويرد بأسلوب كويس — مش إنه يدوّر على بيانات
ولا يحسب أرقام.

## 1.5 رحلة تحريك مرحلة (اللي بتشغّل الرسايل التلقائية)

```
موظف بيدوس زرار "Move to next stage"      أو    بيسحب الكارت في الكانبان
        │                                              │
        └──────────────┬───────────────────────────────┘
                       ▼
        CarDeal.save()  ──►  pre_save()
                              • بيقرأ المرحلة القديمة من الداتابيز
                              • بيحط وقت الدخول للمرحلة الجديدة
                              • لو المرحلة نهائية → الصفقة "تمت"
                       ▼
                        post_save()
                              • بيكتب سطر في StageChangeLog
                              • بيبعت مهمة لـ Celery ترسل للعميل
                       ▼
        Celery: notify_stage_change
              • الرسايل مقفولة؟ → السطر يتسجّل "skipped" وخلاص
              • مفتوحة؟ → جوه 24 ساعة: نص عادي / بره: قالب معتمد
              • فشلت؟ → بيتعمل "نشاط" (activity) لمسؤول الصفقة
```

**نتيجة مهمة جداً:** الهوك مركّب على `save()` — يعني **أي** طريقة لتغيير
المرحلة بتبعت رسالة: الزرار، الكانبان، أوتوميشن، أو تعديل جماعي من الليست.
ده مقصود، وعشان كده في مفتاح "Hold customer messages" على كل صفقة، وعشان كده
بنستورد الصفقات القديمة والمفتاح ده مقفول.
